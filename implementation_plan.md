## User Review Required

> [!IMPORTANT]
> **Authentication Removal**: The plan removes backend auth routes (`auth.py`, `organizations.py`), models (`User`, `Organization`, `Membership`), dependencies (`get_current_user`), and frontend pages (`/login`, `/register`). The `public_projects.py` router already handles project creation without auth — this will become the only project router. The `Organization` and `User` models will be kept as internal system records (auto-created) to avoid breaking FK constraints in the existing DB schema.

> [!IMPORTANT]
> **Questionnaire Scope**: The mock-data wizard currently has ~30 questions across 6 sections. The plan replaces these with **80+ enterprise-level business analysis questions** across 15 sections, each with description, examples, recommended answers, help tooltips, choice selections, custom text fields, optional comments, importance levels, and dependencies. This is a substantial content creation effort.

> [!WARNING]
> **Diagram Generation**: Mermaid diagrams (ER, Class, Sequence, Use Case, Activity, Component, Deployment, State, Data Flow, RBAC, Architecture, Workflow) will be generated as Mermaid syntax strings from interview data. PlantUML and Draw.io export are listed as stretch targets — Mermaid is the primary format since it renders natively in the frontend.

---

## Open Questions

> [!IMPORTANT]
> **BPMN Diagrams**: Full BPMN 2.0 XML generation requires process mining data (swimlanes, gateways) that the interview doesn't model. The plan will generate **simplified Mermaid flowcharts** labeled as workflow/BPMN-style diagrams. Is that acceptable, or do you need actual BPMN XML export?

> [!IMPORTANT]
> **LaTeX Export**: Adding LaTeX export requires a LaTeX compiler (e.g., `pdflatex`) in the Docker image, which adds ~500MB. Should LaTeX export be included now or deferred?

> [!IMPORTANT]
> **Live Updates Architecture**: "Everything updates live" during the interview can be done via (a) polling from the frontend after each answer, or (b) WebSocket/SSE push from the backend. The existing interview already uses request/response per turn. The plan uses **polling after each answer submission** (simpler, already working) plus a new `/projects/{id}/live-preview` endpoint that returns the full current state. Do you prefer WebSocket streaming instead?
